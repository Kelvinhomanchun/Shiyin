# KelNote UX review — 2026-11-23

Panel: interaction designer, information architect, consultant-workflow specialist, accessibility reviewer.
Method: walked the meeting page (List / Mind map / People / Transcript / Ask), the person page (card + 5 tabs) and the Stakeholder Map in real windows at the user's large text size, against the user's job: *prepare for, run, and follow up on client meetings; understand stakeholders; act on commitments.*

## Theme A — Connect people across the app (the user's example)

People are the backbone of the new features, but names are dead text in most places. Every name should be a door to that person.

| # | Recommendation | Where | Effort |
|---|---|---|---|
| A1 | **Clickable owners in Action items** — avatar + name open the person page; hover shows role and quadrant. Unassigned → "Assign…" menu of meeting attendees. | Meeting → Action items table | S |
| A2 | **Clickable attendee chips** in the meeting header → person page (rename moves to the chip's right-click / ⋯, which is the less common action). | Meeting header | S |
| A3 | **Clickable names in People view and transcript** — the "Kelvin / Sandy" headings and the speaker label on each transcript line open the person page. | Notes → People, Transcript | S |
| A4 | **Person hover card** — hovering any linked name shows a mini card: role, quadrant, attitude, trust, last met, open action items, "Open profile". Lets you check someone without leaving the meeting. | Everywhere A1–A3 | M |

## Theme B — Action items as a real follow-up tool

Action items are where meetings turn into work, but they are read-only text spread across meetings.

| # | Recommendation | Effort |
|---|---|---|
| B1 | **Mark done** — a checkbox per item (synced with Reminders when added there). Done items go grey and move to the bottom. | M |
| B2 | **My action items** view in the sidebar (under All meetings / People): every open item owned by you across meetings, grouped *Overdue / This week / Later / No date*, each linking back to the moment in the meeting. | M |
| B3 | **Overdue highlighting** — due dates in the past turn red; "today" amber. | S |
| B4 | **Inline edit of owner/due** — click owner → pick attendee; click due → date picker (today it needs the whole notes editor). | M |

## Theme C — Meeting page hierarchy

| # | Recommendation | Effort |
|---|---|---|
| C1 | **Meeting brief strip** above the notes tabs: "3 decisions · 4 action items (2 yours) · 5 to confirm" — each a jump link. Gives the 5-second read before you dive in. | S |
| C2 | **Stakeholder lens on the meeting** — a small row of attendee chips coloured by attitude with their quadrant, linking to "Plan" for each. Bridges the meeting and the stakeholder analysis. | M |
| C3 | **Timestamps quieter** — they currently compete with the text (same size, grey). Smaller, right-aligned, shown in full on hover. | S |
| C4 | **Ask answers: citations as chips** — the Ask tab shows citations as raw transcript lines in a long list; show them as compact "20:26 ▸" chips with the quote on hover, and keep the answer readable. | S |

## Theme D — Before-meeting preparation (consultant workflow)

| # | Recommendation | Effort |
|---|---|---|
| D1 | **Prep brief for a folder / upcoming meeting** — pick attendees (or a folder) → one page combining each person's *Plan* tab (next-meeting objective, questions, avoid, working-with-you), open commitments both ways, and last decisions. Exportable as PDF/Markdown. | L |
| D2 | **Commitments tracker** — "us → them" and "them → us" promises from all stakeholder profiles in one list per folder, so nothing you promised a client slips. | M |

## Theme E — Consistency & accessibility

| # | Recommendation | Effort |
|---|---|---|
| E1 | **One link colour, one rule**: celadon = navigates; grey = metadata; speaker colours only on avatars (names are currently coloured per speaker *and* sometimes links, which reads as "clickable" inconsistently). | S |
| E2 | **Keyboard**: ⌘1–⌘5 switch person-page tabs; ⌘[ / ⌘] back/forward between meeting ↔ person after following a link. | S |
| E3 | **Back navigation** — after jumping from a meeting to a person (A1–A3), a "← Regular Progress Update" breadcrumb returns you to the same scroll position. | M |
| E4 | **Large-text audit** — the user runs a large content text size; add it to the standard check (badges, tab bar, tables) so overflow regressions (as seen twice today) don't recur. | S (process) |

## Suggested bundles

- **Quick win (≈ half a day):** A1, A2, A3, B3, C3, E1, E4
- **Follow-up workflow:** B1, B2, B4, D2
- **Stakeholder-in-context:** A4, C1, C2, E3
- **Meeting prep:** D1
